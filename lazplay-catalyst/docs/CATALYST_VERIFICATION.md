# Catalyst Verification Notes

Verified against official Catalyst documentation on 2026-05-18:

- CLI install and first commands: `npm install -g zcatalyst-cli`, `catalyst --version`, `catalyst login`, `catalyst init`, `catalyst serve`, `catalyst deploy`.
- Project deploy requires root `catalyst.json`; API Gateway deploy requires root `catalyst-user-rules.json`.
- CLI deploy supports `--only client`, `--only appsail`, `--only functions`, and `--only apig`.
- AppSail managed runtimes include Node 16, Node 18, and Node 20.
- AppSail `app-config.json` examples currently use `buildPath`, `stack`, `command`, `env_variables`, `memory`, and lifecycle scripts.
- Node AppSail should listen on `process.env.X_ZOHO_CATALYST_LISTEN_PORT` with a local fallback.
- Node Functions support Node 20 and require `catalyst-config.json` in each function root.
- Catalyst Cache segments must be created in the console; cache item TTL defaults to 48 hours and can be overridden up to 48 hours.
- Catalyst Data Store table schema is created in the console or API. CLI `ds:import`/`ds:export` is for rows, not schema creation.
- Catalyst IaC export/import ZIPs require `project-template.json`, but current docs state the JSON is generated by Catalyst export and cannot be manually generated as a supported workflow yet.
- Catalyst Data Store default columns are `ROWID`, `CREATORID`, `CREATEDTIME`, and `MODIFIEDTIME`.
- ZCQL is available from the Node SDK through `app.zcql().executeZCQLQuery(query)`.
- Catalyst deployment rejects environment variables that collide with reserved platform keywords. Lazplay custom deployment variables are namespaced with `LAZPLAY_`.

Local verification:

- The `catalyst` executable is not installed in this workstation PATH, so commands that require the CLI were documented and scripted but not executed here.
