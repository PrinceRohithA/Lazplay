# Deployment

## Prerequisites

Install the current Catalyst CLI:

```powershell
npm install -g zcatalyst-cli
catalyst --version
catalyst login
```

The CLI is not installed in this local PATH at the time this scaffold was generated.

## One-Time Catalyst Setup

1. Create or select the Lazplay Catalyst project in the Catalyst console.
2. From `lazplay-catalyst/`, run `catalyst init` if this directory needs to be linked to a different Catalyst project.
3. Create the Cache segments listed in `iac/cache-segments.json`.
4. Copy segment IDs into `backend/app-config.json` `env_variables`.
5. Create Data Store tables and columns from `iac/datastore.schema.json`.
6. Enable API Gateway:

```powershell
catalyst apig:enable
```

The checked-in API Gateway file follows the documented `source_endpoint`, `target_endpoint`, `target`, `method`, and `throttling` shape. If your CLI build requires numeric target IDs instead of `target_name`, deploy or initialize the AppSail/function targets once, run `catalyst pull --only apig`, and keep the pulled target IDs in `catalyst-user-rules.json`.

Custom deployment environment variables use the `LAZPLAY_` prefix. Do not define custom variables with `CATALYST_`, `X_ZOHO_`, `ZOHO_`, or `NODE_` prefixes in Catalyst config files; Catalyst reserves platform environment keywords and rejects deploys with `environment_variables must not contain reserved keywords`.

## Local Build

```powershell
.\scripts\validate.ps1
.\scripts\build.ps1
```

If PowerShell execution policy blocks a local script, use:

```powershell
powershell.exe -ExecutionPolicy Bypass -File .\scripts\validate.ps1
```

## Local Serve

```powershell
.\scripts\serve.ps1
```

Official Catalyst docs say `catalyst serve` serves client, functions, and AppSail locally, but AppSail does not currently get live watch mode.

## Development Deploy

```powershell
.\scripts\deploy.ps1
```

Equivalent explicit command:

```powershell
catalyst deploy --only client,appsail,functions,apig
```

Catalyst CLI deployment updates the development environment. Promote to production from the Catalyst console after smoke testing.

## Troubleshooting

If deployment fails with `environment_variables must not contain reserved keywords`, run:

```powershell
powershell.exe -ExecutionPolicy Bypass -File .\scripts\validate.ps1
```

Then check `backend/app-config.json` and `functions/*/catalyst-config.json` for custom keys outside the `LAZPLAY_` namespace.

## IaC Export And Import

Catalyst supports project export/import ZIPs through:

```powershell
catalyst iac:export
catalyst iac:pack
catalyst iac:import
```

Current Catalyst docs say `project-template.json` is generated by Catalyst export and cannot be manually generated as a supported workflow yet. For that reason, the root `project-template.json` in this scaffold is only a draft marker. After creating the Data Store tables and Cache segments, run `catalyst iac:export` and replace the draft marker with the exported file before using `iac:pack` or `iac:import`.

## Production Checklist

- Replace all `CHANGE_ME` values in `backend/app-config.json`.
- Set R2 credentials and bucket names.
- Set Catalyst Cache segment IDs.
- Set Razorpay secrets.
- Confirm API Gateway routes target `lazplay-api`.
- Verify the web client points to the production API with `VITE_API_URL`.
- Confirm no large object is proxied through AppSail.

## Rollback

- Use Catalyst console deployment history for AppSail rollback.
- Re-deploy the previous `catalyst-user-rules.json` for API Gateway rollback.
- Keep R2 manifest object keys immutable so launchers can be pointed back to the prior manifest.
- Export Data Store rows before schema changes and re-import if needed.
